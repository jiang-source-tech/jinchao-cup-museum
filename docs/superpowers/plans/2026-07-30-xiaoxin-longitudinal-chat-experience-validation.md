# 小芯长期聊天交互与个体成长测试计划

日期：2026-07-30

时区：Asia/Shanghai（UTC+8）

计划编号：XIAOXIN-LONGITUDINAL-01

当前状态：待执行

验证对象：`CompanionMind` 长期记忆、个体人格、关系成长、主动陪伴与真实 ESP32 聊天体验

研究合同：[小芯个体辨识与长期成长验证方案](../research/2026-07-25-xiaoxin-longitudinal-individuality-validation.md)

验证台账：[小芯个体成长验证台账](../../verification/xiaoxin-individuality/README.md)

## 1. 目标

本计划验证的不是模型在单轮上下文中能否复述几分钟前的信息，而是整个长期陪伴架构经过数周、数月和四学年使用后，是否仍然能够：

- 准确保留重要个人事实；
- 在新会话、设备重启和服务重启后继续召回；
- 正确处理纠正、遗忘、过期和关系重置；
- 形成稳定但不过度固化的个体表达；
- 随真实跨日互动发展关系，不依赖聊天次数刷级；
- 在四学年变化中保持连续性，不虚构共同经历；
- 保证不同学生、设备和记忆主体完全隔离；
- 让用户真实感受到“小芯越来越懂我”；
- 不增加烦扰感、监控感和错误主动关心。

短轮上下文问答只作为链路冒烟检查，不作为长期记忆通过证据。

## 2. 验证边界

测试覆盖完整生产链路：

```text
真实互动
  -> Companion Evidence 采集与候选确认
  -> Evidence 生命周期、纠正、遗忘与过期
  -> Capsule / Adjustment / Chapter 异步整理
  -> 出生气质 / 小芯年龄 / 关系阶段 / 关系姿态 / VA
  -> CompanionPolicy
  -> Prompt 与新会话回复
  -> 用户反馈、控制与下一轮状态
```

数据库中存在字段、任务执行成功或接口返回 200 均不等于产品通过。最终必须同时具有：

1. 可复核的架构正确性证据；
2. 跨会话、跨重启的真实真机证据；
3. D7、D30、D90 用户可感知结果；
4. 记忆、控制、烦扰和监控感门禁结果。

## 3. 两条证据链

### 3.1 加速纵向重放

将 D0、D7、D30、D90 和四学年事件压缩执行，用于验证：

- 长期状态机和事实源正确；
- Evidence 血缘、替代、撤销和过期正确；
- 异步整理、重放和故障恢复幂等；
- 关系、年龄、相处时长和人格轴线保持独立；
- 大规模历史噪声下召回仍然准确。

加速重放不能代替真实 D7、D30、D90 使用，也不能用来证明烦扰感、监控感和长期个体辨识。

### 3.2 真实纵向使用

使用真实 ESP32、真实语音链路和冻结候选服务端持续运行到 D7、D30、D90，用于验证：

- 用户能否感到个体差异；
- 个体差异是否随时间形成而非随机漂移；
- 主动陪伴是否相关且不过度；
- 用户纠正、遗忘和边界是否持续生效；
- 真机语音、字幕、表情和长期投影是否一致。

## 4. 检查点日期

以 2026-07-30 为 D0：

| 检查点 | 日期 | 主要裁决 |
|---|---|---|
| D0 | 2026-07-30 | 版本、身份、数据库和初始人格基线 |
| D7 | 2026-08-06 | 初始气质是否可感知，是否过早适应 |
| D30 | 2026-08-29 | 相处调整是否产生增量价值，纠正和遗忘是否可靠 |
| D90 | 2026-10-28 | 长期辨识、保持、漂移、烦扰和监控感 |

真实检查点未发生前不得创建伪造结果，也不得提前标记为 `PASS`。

## 5. 版本冻结

每批测试开始前生成不可变 baseline manifest，至少记录：

| 对象 | 必须记录的标识 |
|---|---|
| 固件 | 版本、完整 ELF SHA-256 |
| 服务端 | Git SHA |
| 数据库 | schema version、备份摘要、完整性结果 |
| 基础模型 | 模型名称和可用版本标识 |
| Prompt | Prompt SHA-256 |
| Policy | Policy SHA-256 |
| 出生气质 | generator version |
| VA | config SHA-256 |
| 真机 | 串口、MAC、UUID、板型 |
| 主体 | account、pet、memory subject、relationship epoch 的隔离绑定 |

固件、服务端、Prompt、Policy、模型或数据库 schema 变化后，不得把新旧证据合并成同一批结果。

## 6. 测试主体

| 主体 | 长期轨迹 | 主要风险 |
|---|---|---|
| A 稳定型 | 兴趣、作息和表达偏好长期一致 | 无法形成稳定调整 |
| B 变化型 | 兴趣、目标和表达需求发生变化 | 旧判断无法退出 |
| C 矛盾型 | 口误、否认和反复纠正 | 新旧事实同时生效 |
| D 稀疏型 | 每周只有少量互动 | 低证据状态错误升级关系 |
| E 高频型 | 每天大量普通闲聊 | 把聊天次数误当关系质量 |
| F 边界型 | 明确拒绝某类主动关心 | 边界被隐式适应绕过 |
| G 非标准学业型 | 转专业、休学、复学或延期 | 套用错误四学年叙事 |
| H 新绑定大二 | 小芯年龄为 2，但关系为初见 | 虚构大一共同经历 |
| 真机 A/B | COM5、COM6 绑定独立主体 | 跨设备或跨主体泄漏 |

所有加速重放和 HIL 使用隔离测试主体与合成事实，不使用生产用户私人数据。

## 7. 语料与事件分布

纵向语料不得只包含高价值事实。建议分布：

- 70% 至 80% 普通闲聊、知识问答和低价值内容；
- 约 10% 稳定偏好、真实经历和长期目标；
- 约 5% 纠正、否定、遗忘和明确边界；
- 约 5% 年级变化、成长事件和关系相关反馈；
- 额外混入相似人名、相近课程、临时安排、已过期事实和 ASR 错误。

语料必须包含事实重复、延迟到达、乱序、同义表达和相互矛盾的输入，以验证真实长期噪声下的召回与整理。

## 8. 防止模型上下文作弊

每个模拟自然日结束后必须：

1. 关闭当前 WebSocket 会话；
2. 丢弃模型对话上下文；
3. 清空仅属于本轮的会话缓存；
4. 在预定检查点重启服务端；
5. 使用全新连接开始下一自然日；
6. 只允许通过 `CompanionMind` 生产投影召回历史。

任何仍携带上一轮模型消息的结果只算短期上下文结果，不计入长期记忆指标。

## 9. 执行阶段

### 阶段 0：冻结基线

操作：

- 备份 `data/xiaoxin_companion.db`；
- 执行 SQLite integrity 和 foreign key 检查；
- 生成版本绑定和 baseline manifest；
- 确认 COM5、COM6 的唯一设备身份；
- 冻结测试主体和分组。

产物：baseline manifest、数据库备份及摘要、设备身份清单。

### 阶段 1：建立纵向语料

操作：

- 为八类主体生成 D0 至 D90 的事件日历；
- 建立大一至毕业和非标准学业路径；
- 标注事实、临时状态、关系 Evidence、纠正、遗忘和边界；
- 为每个预期变化记录依据和禁止结果。

产物：冻结纵向 corpus、事件字典、预期状态清单。

### 阶段 2：搭建加速重放

操作：

- 按自然日开启和关闭独立会话；
- 使用可控的 Asia/Shanghai aware datetime；
- 运行真实 `CompanionMind`、SQLite 和 due work；
- 保存每次 Evidence、派生对象、Policy 和 Prompt 投影摘要；
- 禁止以内存假 Store 替代真实临时 SQLite。

产物：replay manifest、结构化事件流、重放审计记录。

### 阶段 3：运行 D0 至 D90 加速验证

操作：

- 验证出生气质稳定；
- 验证 candidate、trial、active 调整演化；
- 验证反向 Evidence、纠正、遗忘和过期后的重算；
- 验证关系升级需要跨日期可靠 Evidence；
- 验证高频闲聊不能刷关系；
- 验证稀疏使用不会被惩罚或虚构熟悉；
- 验证大量历史噪声下的召回精度和相关性。

产物：accelerated longitudinal report。

### 阶段 4：运行四学年与非标准路径

操作：

- 验证大一到大二保持同一 pet 和当前 relationship epoch；
- 验证年龄变化不会自动推导关系升级；
- 验证大二首次绑定不会生成大一共同经历；
- 验证转专业、休学、复学和延期不会套用错误章节；
- 验证成长时刻失败可重试、成功后不重复。

产物：academic longitudinal report。

### 阶段 5：故障注入与恢复

在以下位置强制终止、重启或失败：

- Evidence 已写入、Capsule 尚未生成；
- Adjustment 状态迁移过程中；
- 成长时刻 reserved 后、delivered 前；
- SQLite WAL 尚未 checkpoint；
- 模型整理超时或返回畸形内容；
- 两个会话并发纠正同一事实；
- schema migration 过程中；
- 数据库备份恢复后；
- 服务端或模型版本升级后的首次召回。

通过要求：幂等、可恢复、不丢失、不重复、不复活已撤销或旧 epoch 内容。

产物：resilience report、恢复前后数据库摘要、故障事件日志。

### 阶段 6：真实 ESP32 HIL 基线

操作：

- COM5、COM6 分别绑定唯一测试主体；
- 采集固件、串口、网络和服务端证明；
- 验证冷启动、对话、重启、重连和服务恢复；
- 验证双设备不串用私人投影；
- 验证语音、字幕、表情和服务端长期状态一致。

产物遵循验证台账中的 HIL bundle：

```text
hil-run/
  manifest.json
  capture-attestation.json
  events.jsonl
  serial.jsonl
  server.jsonl
  network.jsonl
  report.json
```

### 阶段 7：真实 D7、D30、D90 使用

每个真实主体每天自然使用 5 至 15 分钟：

- 约 80% 自由聊天，约 20% 固定探针；
- 不查看后台状态后再决定如何提示系统；
- 不为帮助系统通过而重复灌输事实；
- 错误记忆按真实用户方式纠正；
- 记录主动陪伴是否相关、重复、烦人或产生监控感；
- 每个检查点冻结回复，用于双盲 2AFC。

产物：D7、D30、D90 checkpoint records 与用户体验记录。

### 阶段 8：盲评与最终裁决

操作：

- 复用预注册 2AFC 合同；
- 分别评估 `style_only` 和 `whole_companion`；
- 比较当前策略、匹配反事实策略和 D7 冻结策略；
- 使用参与者聚类 bootstrap，不把同一人的多题当作独立样本；
- 汇总准确性、召回、相关性、纠正、遗忘、烦扰和监控感。

产物：research report、checkpoint report、controlled rollout report。

## 10. 必测纵向故事

- 出生气质按 pet 一次生成并终身稳定；
- 跨日可靠 Evidence 才能推动关系变化；
- 高频闲聊不能刷高关系阶段；
- 相处调整按 candidate、trial、active 合理推进；
- 反向证据能够撤销已有调整；
- 纠正后旧事实不得继续进入 Prompt；
- 遗忘后 Evidence、Capsule、Chapter 和主动陪伴全部失效；
- 关系重置保留用户事实并移除旧共同关系经历；
- 年龄、关系阶段和相处时长互不推导；
- 大二首次绑定不生成大一共同经历；
- 非标准学业路径不产生标准四年虚假章节；
- 模型失败后整理任务可重试且不重复；
- COM5 与 COM6 之间私人记忆泄漏为零。

## 11. 放行门槛

复用现有 checkpoint 合同：

| 指标 | 门槛 |
|---|---:|
| 跨主体、过期、遗忘、撤销引用 | 0 |
| 记忆引用准确率 | >= 98% |
| 准确率置信区间下界 | >= 95% |
| 明确召回成功率 | >= 85% |
| 召回率置信区间下界 | >= 75% |
| 记忆引用相关率 | >= 90% |
| 相关率置信区间下界 | >= 85% |
| 纠正成功率 | 100% |
| 遗忘成功率 | 100% |
| 遗忘后再次出现 | 0 |
| 双设备私人记忆泄漏 | 0 |
| 重复成长表达 | 0 |
| 主动陪伴烦扰或监控感增长 | 不得显著增加 |

个体辨识和成长辨识阈值、样本量、分组、失访和 bootstrap 规则以冻结研究合同为唯一依据，不在本计划中建立第二套数值来源。

优先复用现有：

- policy matrix gate；
- memory truth gate；
- real ESP32 HIL gate；
- longitudinal research gate；
- checkpoint outcome gate；

本计划本身不要求为每个纵向故事新增一个自动化测试。实际实施任务默认新增 0 至 3 个聚焦用例；预计超过 3 个时，必须先逐项说明额外用例保护的具体回归风险并取得用户明确同意。

## 13. 裁决规则

- 出现任一跨主体泄漏、遗忘复活、撤销复活或错误关系重置，立即 `FAIL`；
- 缺少真实 D7、D30、D90 样本时只能是 `INCONCLUSIVE`；
- 加速重放通过但真实体验失败，整体仍为 `FAIL`；
- 数据库状态正确但用户无法感知个体差异，产品体验不通过；
- D90 个性辨识显著低于 D30，长期保持不通过；
- 版本绑定不完整或证据混用其他版本，整批证据无效；
- 只有两台设备时可以完成架构和 HIL 试点，不能替代正式统计研究。

## 14. 停止条件

以下任一条件出现后停止后续阶段，先修复再重新建立基线：

- 私人状态跨 subject、pet、device 或 relationship epoch 泄漏；
- 被遗忘、被替代或已撤销内容重新进入 Prompt；
- 同一成长时刻或主动陪伴重复投递；
- 数据库完整性、外键或迁移恢复失败；
- 固件、服务端、Prompt、Policy 或模型版本无法绑定；
- 真机日志无法关联到唯一设备和唯一事件；
- 测试通过依赖保留模型上下文。
