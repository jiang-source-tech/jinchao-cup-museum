# 仅保留云端 ASR 实施计划

本文是 2026-07-02 的历史实施计划归档。原目标是在小芯第一阶段部署中移除本地和自托管 ASR 路径，只保留云端流式 ASR。

## 目标

降低 4 核 8GB、无 GPU 服务器的部署压力，把语音识别交给云端供应商，减少本地模型、挂载目录和容器依赖。

## 实施任务

1. 切换默认 ASR 配置，移除本地 ASR 默认项。
2. 清理本地和自托管 ASR 的运行时文件。
3. 移除 Docker 挂载和依赖中不再需要的 ASR 模型路径。
4. 更新 active docs，让部署文档不再推荐本地 ASR。
5. 运行配置、导入和基础链路验证。

## 验收

- 默认配置使用云端 ASR。
- 首次部署不需要下载或挂载本地 ASR 模型。
- 服务端仍能完成 ESP32 语音链路。

## 风险

云端 ASR 会引入供应商延迟、网络可用性和 API Key 管理问题。第一阶段接受这个代价，换取部署简单和资源占用可控。
