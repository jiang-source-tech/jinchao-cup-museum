# 小芯独立身份与记忆控制台实施计划

本文是 2026-07-04 的历史实施计划归档。原目标是为小芯控制台增加独立账号、设备绑定、说话人管理和记忆主体隔离。

## 目标

解决“多人共用设备或说话人不稳定导致记忆污染”的问题。每轮对话必须解析到稳定、唯一、不可读的 `memory_subject_id`，而不是直接使用 `speaker` 文本或 `device_id` 作为长期记忆 scope。

## 核心设计

- 使用本地 SQLite 保存账号、session、设备、说话人、记忆主体和 alias。
- 第一阶段不复用 8002 管理后台用户体系。
- 控制台 API 必须按当前登录用户过滤设备和记忆主体。
- 未登录不能访问控制台敏感 API。
- SQLite 不可用时宁可降级为不写长期记忆，也不能写入全局记忆。

## 实施任务

1. 建立 SQLite identity store。
2. 建立认证服务和 session cookie。
3. 让控制台运行时携带身份服务。
4. 增加登录、登出、当前用户和 session 强制校验接口。
5. 增加设备所有权和绑定能力。
6. 实现身份解析器。
7. 让 Xiaoxin runtime 使用 `memory_subject_id`。
8. 增加说话人和记忆主体 API。
9. 增加记忆主体检查和控制能力。
10. 增加 legacy memory 列表和文档。
11. 做端到端验证。

## 验收

- 已绑定设备和确认说话人写入用户说话人主体。
- 已绑定设备但未知说话人写入设备未知主体。
- 未绑定设备写入设备 fallback 主体，不污染用户主体。
- alias 异常链会被拒绝或截断。
- 控制台只能操作当前账号绑定的设备和记忆主体。

## 当前状态

该计划支撑 `XIAOXIN-004` 和 `XIAOXIN-005`。在真实产品化前，这仍是 P0 级待完成闭环。
