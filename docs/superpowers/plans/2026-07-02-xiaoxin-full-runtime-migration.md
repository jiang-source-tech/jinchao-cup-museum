# 小芯完整人格与知识运行时迁移实施计划

本文是 2026-07-02 的历史实施计划归档。原目标是把 `D:\AI_Pet\hzcu_xiaoxin` 中的小芯数字学姐能力迁移到 ESP32 服务端 `main/xiaozhi-server` 中。

## 目标

小芯迁移不是只改提示词。目标能力包括人格、校园知识、语义路由、边界处理、分层记忆、关系成长状态、回复修复和 TTS 风格对齐。

## 架构选择

选择在服务端进程内新增：

```text
main/xiaozhi-server/core/xiaoxin/
```

外部只暴露一个运行时入口，由现有连接流程调用：

```python
xiaoxin_runtime.handle_turn(...)
```

小芯运行时负责普通对话、校园知识问答、记忆读写、边界兜底和回复修复。设备动作、音乐、IoT、退出、WebSocket 生命周期和 TTS 仍由现有 `ConnectionHandler` 负责。

## 实施任务

1. 建立测试框架和 `core/xiaoxin` 包结构。
2. 迁移知识库、语义路由和边界模块。
3. 迁移 profile、companion、episodic、growth arc、relationship 等分层记忆。
4. 建立提示词构造、LLM 适配器和运行时编排。
5. 增加配置项并同步小芯人格与 TTS 风格。
6. 在特性开关后接入 `ConnectionHandler`。
7. 跑单元测试和手动 smoke 验证。

## 验收

- 校园问题只能基于已迁移知识回答，资料不足时明确说明没有可靠资料。
- 记忆问题可以召回已提交且安全的长期记忆。
- “忘掉我刚才说的专业”等记忆控制命令能更新存储。
- “帮我联系老师”等越界请求会自然拒绝并给出用户可自行操作的建议。
- “拜拜”等设备动作仍走原有退出路径。
- TTS 风格是小芯数字学姐，不是上游小智人格。
- 音乐、IoT 和其他工具行为在明确匹配时仍可用。

## 风险

最大风险是小芯运行时和原有函数调用、流式输出之间互相抢职责。设计上通过“普通对话归小芯，设备动作归原链路”降低耦合，并保留 `xiaoxin_runtime.enabled` 开关。
