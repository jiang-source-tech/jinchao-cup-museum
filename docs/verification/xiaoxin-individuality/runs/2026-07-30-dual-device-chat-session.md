## 2. 真实性纪律

1. 只记录已经实际发生、实际听到、实际看到或能由原始日志复核的事实。
2. 操作者原话、ASR 识别文本、设备回复原文是三个不同字段，不得互相代填。
3. 无法听清、看清或从日志确认时，填写 `未知`、`未捕获` 或 `待核对`，不得根据上下文补全。
4. 表情和动作按屏幕或实体设备实际呈现记录；提示词期望的表情不能写成实际呈现。
5. 所有时间使用本机 `Asia/Shanghai` 时区并尽可能精确到毫秒。人工估计的时间必须标记为 `估算`。
6. 响应延迟至少区分“说话结束到首个可观察响应”和“说话结束到开始播音”；缺少可靠时间戳时不填推算值。
7. 每轮优先分配唯一 `event_id`。串口、服务端、网络和数据库证据必须通过同一事件 ID 或明确的时间窗口关联。
8. 人工体验判断不得覆盖机器证据；机器日志成功也不能替代对回复内容、声音、字幕、表情和动作的人工观察。
9. 发现身份串用、错误召回、旧状态复活、纠正/遗忘失败时原样记录，不在原记录上改写。后续修复复测必须新建轮次。
10. 本次两台设备不能证明 D7、D30、D90 纵向效果，也不能代替正式参与者研究。

## 5. 记录口径

### 5.1 时间点

- `t_start`：操作者开始说话。
- `t_end`：操作者说话结束。
- `t_first_response`：设备首次出现可观察反馈（屏幕、提示音、动作或文字）。
- `t_audio_start`：设备开始播放回复语音。
- `t_audio_end`：设备回复语音播放结束。
- `首响应延迟_ms = t_first_response - t_end`。
- `播音启动延迟_ms = t_audio_start - t_end`。

### 5.2 结果枚举

- `PASS`：本轮目标得到直接、可复核的满足，且未发现冲突证据。
- `FAIL`：已观察到违反本轮目标的行为。
- `INCONCLUSIVE`：证据缺失、歧义或采集失败，无法裁决。
- `NOT_RUN`：尚未执行。

### 5.3 表情与动作

分别记录表情名称/视觉描述、动作名称/视觉描述、开始时间和持续时间。若串口日志给出内部表情 ID，同时记录“实际视觉表现”和“内部 ID”；两者不一致时记为异常。

### 11.6 加速回归裁决

**固定版本与模拟时间条件下的加速长期回归失败。**

失败由已观测行为直接支持：主 D1 双机召回失败、D3 双机旧目标未 supersede、D7 双机自然目标/习惯使用失败、D30 的 B 端顺从 A 主体错误前提、D90 双机均未正确召回 D3 更新后的当前目标。D1B 的两次自然任务通过、D30 的 A 子项通过和 D90 的局部事实保持不能抵消这些失败。

严格解释：本裁决汇总的是“各检查点在其记录版本与模拟时间条件下”的失败，不是单一 SHA 从 D1 连续运行到 D90 的结果。版本在首次 D3 后发生了两次测试支持代码变更，不能据此声称完成了单版本连续加速稳定性证明。

该结论不是“真实经过 D1/D3/D7/D30/D90 后失败”。所有检查点均在 `2026-07-30` 当天执行，模拟时间只由 API `simulated_as_of` 提供。它不证明真实历时稳定性、真实关系成长、长期硬件/网络可靠性、用户长期体验或统计效果。
