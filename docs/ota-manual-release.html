Lesson 0001 · OTA Release Operations

手动发布一个小芯 OTA 新版本

完成这节课后，你能独立完成：修改版本号、干净构建、发布前校验、上传服务器、创建单设备灰度、观察 committed、紧急暂停，以及逐步放量。

当前项目的特殊事实：可工作的 OTA 固件基线目前在 origin/codex/ota-firmware-bootstrap，尚不能默认用任意 main 构建。服务器当前还是开发用 HTTP OTA，正式对外发布前应改为 HTTPS。

先记住发布链路

1

固件版本

版本号必须写进固件，且高于设备当前版本。

2

构建与校验

生成 ai_pet.bin，确认尺寸、分区表与 SHA-256。

3

不可变制品

上传到服务器收件箱，再由发布脚本按哈希导入。

4

发布元数据

登记版本、机型、板型、分区布局和渠道。

5

单设备灰度

比例保持 0%，只把测试板加入允许名单。

6

验收与止损

看到 committed 才算成功；异常立即 paused。

1创建干净的发布工作树

以下示例发布 0.1.3。每次发布都替换成新的、更高版本号。

# Windows PowerShell
$Version = "0.1.3"
$FirmwareRepo = "D:\Learn\hzcu_xiaoxin_firmwire_private"
$ReleaseDir = Join-Path $FirmwareRepo ".worktrees\ota-release-$Version"

Set-Location $FirmwareRepo
git fetch origin
git worktree add -b "release/ota-$Version" $ReleaseDir origin/codex/ota-firmware-bootstrap
Set-Location $ReleaseDir
git status --short --branch

最后一条命令不应出现未知改动。使用独立工作树的目的，是不覆盖原目录中属于你的 sdkconfig 改动。

2修改固件内嵌版本号

打开新工作树的 CMakeLists.txt，把：

set(PROJECT_VER "0.1.0")

改为：

set(PROJECT_VER "0.1.3")

同时确认 sdkconfig 的 Audio Codec 配置区包含下列已验证配置：

# CONFIG_CODEC_I2C_BACKWARD_COMPATIBLE is not set
版本号不是文件名。只把文件改名为 0.1.3.bin 没用；设备判断的版本来自固件内部的 PROJECT_VER。

3构建固件

# 仍在 Windows PowerShell，并位于发布工作树
& "D:\Espressif\frameworks\esp-idf-v5.5.4\export.ps1"
idf.py build

成功时输出必须包含：

  • App "ai_pet" version: 0.1.3
  • Generated .../build/ai_pet.bin
  • 固件小于 0x600000，并显示剩余空间

4运行发布前校验

$OtaTests = Get-ChildItem -LiteralPath "tests" -Filter "ota_*.py" |
  Sort-Object Name |
  ForEach-Object { $_.FullName }

python -m pytest -q @OtaTests
python tools\verify_xiaoxin_ota_release.py --build-dir build

$Bin = Join-Path (Get-Location) "build\ai_pet.bin"
$Hash = (Get-FileHash -LiteralPath $Bin -Algorithm SHA256).Hash.ToLower()
$Size = (Get-Item -LiteralPath $Bin).Length
"version=$Version size=$Size sha256=$Hash"

发布门槛：

  • OTA 测试全部通过；当前基线应显示 43 passed。
  • 预检输出以 PASS: 开头。
  • ai_pet.bin 小于 6 MiB。
  • 把 SHA-256 和字节数保存下来，上传后必须逐字核对。

5上传到服务器收件箱

# Windows PowerShell
$Server = "<服务器IP>"
scp ".\build\ai_pet.bin" `
  "jiang@${Server}:/opt/xiaoxin-work/xiaoxin-esp32-server/main/xiaozhi-server/data/ota-inbox/ai_pet-$Version.bin"

输入服务器密码后等待传输完成。接着登录服务器：

ssh "jiang@$Server"

6在服务器核对文件

# 以下均在服务器 Bash 中执行
cd /opt/xiaoxin-work/xiaoxin-esp32-server/main/xiaozhi-server

VERSION="0.1.3"
SOURCE="data/ota-inbox/ai_pet-$VERSION.bin"

sha256sum "$SOURCE"
stat -c '%s bytes' "$SOURCE"

这里的哈希和大小必须与 Windows 构建机完全一致。任何一个不一致都停止发布并重新上传。

7选择单台测试设备

下面命令从最近一次成功 OTA 的审计记录中选择测试设备，但不把设备标识打印到屏幕：

DEVICE_ID=$(docker exec xiaozhi-esp32-server python -c "import sqlite3; q=sqlite3.connect('data/xiaoxin_firmware_releases.db'); r=q.execute(\"SELECT device_id FROM firmware_release_observations WHERE result='committed' ORDER BY observed_at DESC LIMIT 1\").fetchone(); print(r[0] if r else '')")

test -n "$DEVICE_ID" && echo "test device selected"
隐私规则：设备 ID、MAC、UUID、热点名称和密码不要粘贴到公开聊天、Issue 或截图中。

8先创建草稿发布

docker exec xiaozhi-esp32-server python scripts/publish_firmware.py \
  --source "$SOURCE" \
  --database data/xiaoxin_firmware_releases.db \
  --artifact-dir data/xiaoxin_firmware \
  --model esp32-s3-touch-lcd-1.46 \
  --version "$VERSION" \
  --board-type esp32-s3-touch-lcd-1.46 \
  --partition-layout-id xiaoxin-ota-16m-v1 \
  --channel stable \
  --esp-idf-version 5.5.4 \
  --rollout-percentage 0 \
  --allow-device "$DEVICE_ID"

命令会把固件按 SHA-256 导入不可变制品目录，并输出 JSON。检查：

  • version 是目标版本。
  • state 是 draft。
  • rollout_percentage 是 0。
  • 复制输出中的 release_id。
RELEASE_ID="<复制上一步输出的 release_id>"

9发布给单台测试板

当前服务器仍使用 HTTP 测试地址，所以必须明确加开发开关：

PUBLIC_OTA_URL="http://<服务器IP>:8003/xiaoxin/ota/"

docker exec xiaozhi-esp32-server python scripts/publish_firmware.py \
  --operation set-state \
  --release-id "$RELEASE_ID" \
  --state published \
  --database data/xiaoxin_firmware_releases.db \
  --artifact-dir data/xiaoxin_firmware \
  --public-ota-url "$PUBLIC_OTA_URL" \
  --allow-insecure-http

rollout_percentage=0 表示普通设备不会收到；允许名单中的测试板仍会收到。

10先监控，再让设备联网

回到 Windows，在发布工作树中另开一个 PowerShell：

& "D:\Espressif\frameworks\esp-idf-v5.5.4\export.ps1"
idf.py -p COM5 monitor

监控启动后再打开手机热点或重启设备。关键成功日志应依次出现：

Current version: 0.1.2
Progress: ...
Progress: 100%
Firmware upgrade successful
App version: 0.1.3
Running a pending OTA image
Pending-OTA transport health probe succeeded
Pending OTA image passed the health window

退出串口监控使用 Ctrl+]。

11服务器验收 committed

docker exec xiaozhi-esp32-server python scripts/publish_firmware.py \
  --operation observations \
  --release-id "$RELEASE_ID" \
  --database data/xiaoxin_firmware_releases.db \
  --artifact-dir data/xiaoxin_firmware

最终成功记录必须满足：

  • event = device_report
  • current_version = 0.1.3
  • target_version = 0.1.3
  • result = committed
  • slot = ota_0 或 ota_1

如果设备已显示新版本但服务器只有 pending，等健康窗口结束后安全重启一次，让设备在下一次 OTA 检查中回传 committed。

12测试结束后暂停

docker exec xiaozhi-esp32-server python scripts/publish_firmware.py \
  --operation set-state \
  --release-id "$RELEASE_ID" \
  --state paused \
  --database data/xiaoxin_firmware_releases.db \
  --artifact-dir data/xiaoxin_firmware

看到输出中的 state: paused 后，本次单设备验收结束。

确认正式放量时怎么做

先在暂停状态下调整比例，再恢复发布：

# 先设 5% 灰度
docker exec xiaozhi-esp32-server python scripts/publish_firmware.py \
  --operation set-rollout \
  --release-id "$RELEASE_ID" \
  --rollout-percentage 5 \
  --database data/xiaoxin_firmware_releases.db \
  --artifact-dir data/xiaoxin_firmware

# 然后恢复发布
docker exec xiaozhi-esp32-server python scripts/publish_firmware.py \
  --operation set-state \
  --release-id "$RELEASE_ID" \
  --state published \
  --database data/xiaoxin_firmware_releases.db \
  --artifact-dir data/xiaoxin_firmware \
  --public-ota-url "$PUBLIC_OTA_URL" \
  --allow-insecure-http

推荐顺序：1 台允许名单 → 5% → 25% → 50% → 100%。每一级都先观察失败率和回滚记录。

发布状态的含义

状态行为什么时候用
draft已登记但不下发检查元数据和哈希
published按允许名单和灰度比例下发测试或正式发布
paused立即停止产生新升级邀约，可恢复测试结束、异常调查
revoked永久撤销，不能再次发布确定固件不可再用

出现问题时的第一动作

出现哈希不符、下载失败、重启循环、回滚或错误版本时，第一动作不是重新上传同名文件，而是把发布状态改为 paused。制品按 SHA-256 不可变；修复后必须使用新的版本号重新构建。

常见错误

  • 只改 BIN 文件名，没有修改 PROJECT_VER。
  • 直接把 BIN 放在目录里，却没有创建发布数据库记录。
  • 使用与设备不匹配的板型或分区布局。
  • 没有核对上传前后的 SHA-256。
  • 发布比例不是 0%，却以为只有测试板会收到。
  • 设备先联网，串口监控后启动，导致丢失关键失败日志。
  • 把 revoked 当成临时暂停；它不能恢复。

检索练习

为什么只把 BIN 放到服务器目录里不够？
因为设备不会扫描目录。服务器必须有发布记录，才能根据版本、型号、板型、分区布局、状态、允许名单和灰度比例决定是否下发。
为什么灰度比例是 0%，测试板仍能升级？
允许名单优先于百分比门控。比例 0% 会挡住普通设备，但明确加入允许名单的设备仍然符合条件。
什么时候使用 paused，什么时候使用 revoked？
不确定、排查中或测试结束时使用 paused，因为可以恢复；只有确定该固件永久不可用时才使用 revoked。
