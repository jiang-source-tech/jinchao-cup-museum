# 小芯博物馆智能伴游系统 PRD

## 文档状态

- 版本：`1.0`
- 日期：2026 年 8 月 9 日
- 状态：`accepted`
- 产品名称：小芯
- 项目名称：小芯：面向博物馆研学的可考证智能伴游系统
- 本期目标：金潮杯比赛可演示产品

本 PRD 是产品范围、用户体验、优先级和验收标准的上位依据。后续架构、协议、数据模型和开发任务必须服务于本 PRD，不得自行增加业务范围。

## 1. 问题陈述

博物馆现有数字导览通常依赖二维码、固定音频和长篇图文。游客能够获得信息，但不一定愿意仔细观察展品、持续提问或完成连续探索。亲子家庭和研学小组尤其容易出现以下问题：

1. 展签文字对儿童过于抽象，家长又不一定具备讲解能力。
2. 固定音频无法响应游客当下真正关心的问题。
3. 通用 AI 虽然能对话，但可能混入模型常识、推测或虚构内容，馆方无法确认回答依据。
4. 一次问答结束后，系统很少继续引导游客观察展品或前往关联展品。
5. 馆方无法方便地发现游客最常问、现有展签却没有覆盖的问题。

用户真正需要的不是一个“什么都能聊”的机器人，而是一个围绕当前展品、使用馆方审核事实、敢于承认资料不足并能引导继续探索的现场伴游。

## 2. 产品方案

小芯是一台面向亲子家庭和研学小组的可携式语音交互终端。每个参观小组在一次临时游客会话中共同使用一台设备。

小芯根据当前路线站点或游客的显式选择确定当前展品。游客直接用语音提问，小芯从当前展品的发布内容中建立依据快照，生成 2 至 4 句短回答，并最多附带一个观察任务或下一站建议。

当资料不足时，小芯明确说明“当前馆方资料没有确认这一点”，不使用模型推测补齐答案。小芯的价值发生在游客面对展品的现场互动中，不把游客再次导向一套重复建设的二维码网页。

馆方通过管理网页维护展品事实、资料来源、审核版本、设备点位和参观路线，并查看高频问题、未命中问题及回答依据。

## 3. 产品定位

### 一句话定位

小芯是一个用馆方审核知识陪游客观察、提问和探索的具身智能伴游。

### 核心价值

- **对游客**：听得懂、问得出、愿意继续看。
- **对家长和教师**：不需要自己掌握完整知识，也能组织一次有互动的参观。
- **对馆方**：回答有依据、内容可维护、游客问题可回收。

### 差异化

| 普通导览 | 通用 AI | 小芯 |
| --- | --- | --- |
| 固定内容 | 能自由对话 | 围绕当前展品对话 |
| 单向播放 | 容易超出资料 | 回答绑定审核事实 |
| 很少引导观察 | 目标不稳定 | 每轮最多一个探索动作 |
| 内容更新依赖技术人员 | 馆方难控制 | 馆方可审核和发布 |

## 4. 目标用户

### 主用户：亲子家庭

典型组成是一名儿童和一名或多名家长，共同使用设备。儿童负责观察和提问，家长可以协助操作，但系统不能要求家长承担讲解员角色。

核心需求：

- 用容易理解的方式解释展品；
- 获得具体、可完成的观察任务；
- 控制讲解长度，避免儿童失去注意力；
- 确保内容不是 AI 随意编造。

### 主用户：研学小组

典型组成是若干学生和一名教师或带队人员。小组围绕一条明确路线完成观察、讨论和回顾。

核心需求：

- 按主题组织连续参观；
- 获得比展签更有互动性的引导；
- 保留本次参观的展品和任务记录；
- 能够区分可靠资料与尚无结论的信息。

### 次级用户：普通游客

希望在有限时间内快速理解重点展品，可以选择普通模式或快速路线。

### 运营用户：馆方内容人员

负责录入展品事实、绑定资料来源、审核发布内容、配置路线和处理未命中问题。

## 5. 使用环境与产品形态

### 使用环境

- 室内博物馆或模拟展区；
- 存在背景人声和间歇噪声；
- 网络质量可能波动；
- 游客通常站立操作，单次停留时间有限；
- 一台设备可能被多个陌生小组连续使用。

### 比赛版设备形态

- 一台 ESP32-S3-Touch-LCD-1.46 可携式终端；
- 麦克风用于语音输入；
- 扬声器用于回答播报；
- 触摸屏用于模式、路线、展品和进度操作；
- 屏幕显示当前展品、知识状态、观察任务和路线进度；
- 设备不承担完整资料阅读；馆方既有二维码可继续独立提供延伸图文、音视频和其他数字内容，小芯不复制这套能力。

### 会话模型

- 一组游客对应一个临时游客会话；
- 会话不要求登录、姓名或声纹；
- 新小组开始前必须结束或重置上一会话；
- 会话保存当前展品、游客模式和路线进度；
- 会话过期后不得被当作长期人物身份继续使用。

## 6. 产品原则

1. **先看展品，再听解释。** 回答应推动观察，不能用长篇播报替代参观。
2. **不知道就明确说不知道。** 资料不足不是系统错误，也不能被模型常识掩盖。
3. **事实不随模式变化。** 普通、亲子和深度模式只能改变表达方式与信息密度。
4. **当前展品必须确定。** 当前展品来自路线、触摸选择或管理员设置，不能由模型猜测。
5. **状态变化必须显式提交。** 展品切换和路线推进不能由模型话术假装完成。
6. **一轮只推进一件事。** 每轮最多提供一个观察任务或下一站建议。
7. **默认不识别游客身份。** 比赛版不建设声纹、长期画像或跨参观记忆。
8. **馆方拥有内容控制权。** 只有审核并发布的内容能够面向游客使用。

## 7. 核心用户流程

### 7.1 开始参观

1. 游客拿到或唤醒设备。
2. 设备创建新的临时游客会话。
3. 游客选择普通、亲子或深度模式。
4. 游客选择自由参观或一条主题路线。
5. 系统根据路线首站或设备默认配置确定当前展品。
6. 屏幕展示展品名称和一句开始提示。

### 7.2 展品互动

1. 游客唤醒小芯并提问。
2. 设备显示聆听状态。
3. 服务端识别问题并读取当前展品。
4. 系统从当前发布内容中建立依据快照。
5. 小芯播放短回答。
6. 屏幕显示知识状态和一个观察任务。
7. 游客可以追问、换一种讲法或进入下一站。

### 7.3 资料不足

1. 游客提出发布内容无法支持的问题。
2. 小芯明确说明馆方资料没有确认。
3. 小芯可以建议一个仍能从现有事实回答的相关角度。
4. 系统把该问题记录为未命中问题。
5. 资料不足不能显示成网络故障或模型错误。

### 7.4 路线推进

1. 小芯可以建议前往下一站。
2. 游客通过语音明确确认或触摸“下一站”。
3. 服务端提交路线进度。
4. 设备收到成功结果后更新当前展品和路线页。
5. 提交失败时保留原站点并显示可重试状态。

### 7.5 结束参观

1. 游客选择结束参观。
2. 设备用简短页面回顾已完成路线、参观站点和本次探索主题。
3. 小芯最多提出一个面向现场的回顾问题，不生成长篇总结。
4. 会话结束，设备清除上一小组的可见状态并返回新会话入口。

## 8. 功能需求

### FR-01 临时游客会话（P0）

- 系统能够创建、查询、结束和过期临时游客会话。
- 会话必须隔离不同参观小组的模式和路线进度。
- 设备启动新会话时必须清除上一小组的可见状态。

### FR-02 当前展品（P0）

- 系统必须始终能够说明当前展品的确定来源。
- 当前展品来源优先级为：游客显式选择、当前路线站点、会话已确认展品、设备默认展品。
- 展品不明确时必须要求选择，不能直接进入事实回答。

### FR-03 展品内容与来源（P0）

- 馆方能够维护展品、别名、图片和展品事实。
- 每条展品事实必须绑定至少一个资料来源。
- 内容支持草稿、审核、发布和撤回状态。
- 游客回答只能使用发布版本。

### FR-04 有依据回答（P0）

- 每轮事实回答必须保存实际使用的事实、来源和内容版本。
- 回答默认 2 至 4 句，适合直接语音播报。
- 回答不能出现依据快照之外的具体年代、人物、地点、材质、工艺、用途或馆方结论。

### FR-05 知识兜底（P0）

- 没有可靠事实时必须使用明确兜底。
- 兜底不得伪装成系统异常。
- 系统记录原问题、当前展品和未命中原因。
- 兜底后最多提出一个有依据的相关观察方向。

### FR-06 游客模式（P0）

- 支持普通、亲子和深度三种模式。
- 模式可以在会话中切换。
- 同一问题在不同模式下必须使用相同事实集合或其子集。
- 亲子模式使用短句和具体观察；深度模式允许更多工艺和历史背景。

### FR-07 连续追问（P0）

- 同一会话内的追问默认延续当前展品。
- 指代不清或明显切换展品时必须澄清。
- 对话历史只保留完成本次参观所需的短期上下文。

### FR-08 语音与设备反馈（P0）

- 设备必须区分待机、聆听、查阅资料、播报、资料不足和系统失败。
- 游客可以中断播报并重新提问。
- 屏幕不得用“已切换”“已进入下一站”等文案提前表示未提交成功的状态。

### FR-09 参观路线（P1）

- 支持快速参观、亲子探索和深度学习三条演示路线。
- 每条路线包含 3 至 5 个有序站点。
- 每个站点包含到站提示和一个观察任务。
- 游客可前进、后退或退出路线。
- 路线切换和推进必须显式提交。

### FR-10 结束参观与现场回顾（P1）

- 游客能够通过触摸或明确语音指令结束本次会话。
- 设备只回顾本次路线、已完成站点和探索主题，不生成新的事实内容。
- 结束后必须清除上一小组的可见状态，再允许创建新会话。
- 小芯不生成游客故事卡、收藏二维码或参观后网页。

### FR-11 馆方管理网页（P1）

- 内容人员能够维护展品、事实和来源。
- 审核人员能够查看版本差异并发布或撤回。
- 管理员能够设置设备默认展区和展品。
- 管理员能够配置路线和站点。
- 管理员能够查看问题、依据、兜底、守卫结果和阶段延迟。

### FR-12 运营洞察（P1）

- 系统统计高频问题、未命中问题和被反复追问的展品。
- 馆方可以把未命中问题转为内容补充任务。
- 比赛版只展示匿名聚合结果，不建立游客个人分析。

### FR-13 演示控制（P0）

- 比赛人员可以从管理网页创建新会话、指定当前展品和重置设备。
- 演示控制不得绕过真实知识检索、LLM、TTS 和真机输出链路。
- 演示模式的特殊操作必须在后台记录中可识别。

## 10. 非功能需求

### 可信性

- 评测集中所有具体事实必须能够映射到实际依据快照。
- 无来源事实不得发布。
- 发布内容撤回后不得继续进入新回答。

### 响应速度

在比赛网络和选定云模型条件下，目标为：

- 从用户说完到首段语音开始播放，`P50 <= 3.0 秒`；
- 从用户说完到首段语音开始播放，`P95 <= 6.0 秒`；
- 模式、路线和展品触摸操作在 `1 秒` 内出现本地反馈；
- 服务端提交失败时设备在 `3 秒` 内进入明确可重试状态。

这些是目标值，不是当前已验证结果。

### 稳定性

- 同一设备应完成至少 30 分钟连续演示而无需人工重启。
- 断线重连后不得错误恢复上一参观小组的会话。
- 重复触摸或重复消息不得造成路线进度重复提交。

### 隐私

- 默认不保存原始音频。
- 不采集姓名、手机号、声纹或长期画像。
- 问题记录使用临时会话标识。

### 可维护性

- 馆方修改展品内容不要求重新训练基础模型。
- 所有发布操作必须留下操作时间和操作者记录。
- 比赛版部署不依赖外部向量数据库或 RAG 管理平台。

## 11. 核心指标

### 比赛验收指标

| 指标 | 目标 |
| --- | --- |
| 发布事实来源完整率 | 100% |
| 有依据问题事实一致率 | >= 95% |
| 明确不可回答问题正确兜底率 | 100% |
| 游客模式切换事实漂移 | 0 次 |
| 路线重复提交 | 0 次 |
| 30 分钟连续真机演示严重故障 | 0 次 |
| 七类核心场景完成率 | 100% |

“事实一致率”必须由预先登记的问题、预期事实和人工复核共同判断，不能让同一个生成模型自评。

### 产品观察指标

以下指标用于试点后判断产品价值，不作为当前已达成结果：

- 每件展品平均主动提问数；
- 观察任务完成率；
- 路线完成率；
- 未命中问题比例；
- 馆方完成一次内容修订所需时间。

## 12. 比赛版验收场景

### 场景 A：可靠事实

游客询问当前展品的材质、年代或工艺。小芯给出短回答，后台能够显示本轮事实、来源和内容版本。

### 场景 B：连续追问

游客用“为什么这样做”“它以前是干什么的”等指代继续提问。系统保持当前展品，不错误切换上下文。

### 场景 C：模式切换

同一问题分别使用亲子和深度模式回答。表达明显不同，但使用的事实不存在冲突。

### 场景 D：知识兜底

游客询问资料中不存在的价格、传说、精确人物经历或馆方结论。系统明确说明资料未确认，不补充模型推测。

### 场景 E：路线与设备同步

游客确认下一站，服务端提交成功后，设备更新站点、当前展品和观察任务；提交失败时不得提前切换。

### 场景 F：结束与重置

游客结束参观后，设备显示简短现场回顾并结束会话。下一小组开始时，设备不得显示上一会话的展品、路线或问题。

### 场景 G：失败恢复

模拟一次网络或模型失败。设备显示系统失败而不是知识兜底，恢复后可以继续当前会话。

## 15. 产品与技术决策

- 设备连接和产品业务通过一个高层对话运行时接口连接。
- 博物馆业务作为独立运行时实现，不继续扩展旧学生陪伴运行时。
- 第一版知识存储采用本地事务型数据库和全文检索。
- 回答依据单位是经过审核并绑定来源的展品事实。
- 当前展品由确定性上下文决定。
- 路线采用确定性状态机。
- 馆方既有二维码内容与小芯保持独立，小芯不作为扫码网页的中间层。
- 比赛部署只启用博物馆业务运行时。
- 旧业务代码在新链路通过真机验收后再删除。

## 16. 测试决策

- 测试最高层可观察行为，不直接测试路由、检索或提示词内部细节。
- 产品核心测试面是“输入游客问题和确定上下文，输出最终伴游结果”。
- 服务端测试检查回答状态、事实 ID、路线状态和审计结果。
- 协议测试检查完整消息的接受或拒绝，禁止部分应用非法状态。
- 真机验收覆盖文字输入到真实设备 TTS、屏幕和触摸反馈。
- 知识评测集与自动化测试分开管理，人工核对事实一致性。

## 17. 风险

| 风险 | 产品处理 |
| --- | --- |
| 尚无真实展馆和授权资料 | 先使用明确标注的演示数据，不声称馆方合作已完成 |
| 展品范围扩张过快 | 先完成 6 至 8 件深度内容，再扩展数量 |
| 云模型延迟或不可用 | 设计明确失败状态和可重复演示问题 |
| 展厅噪声影响识别 | 使用短句交互、文字回显和重新提问路径 |
| 模型生成资料外事实 | 依据快照、确定性守卫和一次修复上限 |
| 旧业务耦合影响新链路 | 先建立高层运行时接口，再切换和删除 |
| 团队把后台做成大而全平台 | 后台只服务内容、设备、路线和运营闭环 |

## 18. 已确认产品决策

以下产品形态已经确认，后续设计和实现不得自行改变：

1. **主用户是亲子家庭和研学小组，普通游客作为次级用户。**
2. **比赛版由一组游客临时使用一台可携设备，不采用一件展品固定安装一台设备的形态。**
3. **当前展品以路线站点和触摸选择为主，第一版不建设二维码识别或摄像头识别。**
4. **小芯不生成故事卡、收藏二维码或参观后网页，不重复建设馆方既有二维码内容。**
