# Prototype Findings

状态：自动审计完成；第 #6 的合成模型、`expression_style` 投影与决策轨迹均已确认。

## 待验证假设

1. 合成不是“后写值覆盖前写值”，而是先形成个体化候选，再依次与年龄和关系包络、用户互动契约、当前场景、负反馈、端侧能力及身份安全门禁求交集。
2. 出生气质表达的是偏好，`initiative_level`、预算和禁止行为表达的是权限或上限，两者不能共用同一个字段。
3. 现有 `CompanionPolicy` 无法在不滥用回复长度、问题预算或 `age_expression` 的情况下承载探索取向、表达活力和思路组织；最小扩展应是一个结构化 `expression_style` 字段，而不是新增人格模块或自由文本 prompt。
4. 决策轨迹应留在 `CompanionMind` 内部用于测试、诊断和安全摘要，不应作为完整工程面板暴露给普通用户。

## 原型结论

2026-07-25 执行非交互审计，七个场景全部通过：

- 短回复契约压住篇幅，但保留活跃表达节奏；
- 禁止主动压住实际权限，但不改写主动型出生气质；
- 初见阶段把深记忆调整限制为一条浅层用户事实，并禁止虚构共同经历；
- 用户低落时把俏皮表达暂时压到克制和无幽默；
- 硬件端把展开表达压到短输出、零追问和零记忆引用；
- “太私人”负反馈立即停止记忆引用、主动延续和关系化收尾；
- 未知说话人整体降级为匿名安全策略。

全部场景都对相同输入执行两次合成并比较规范化结果。结果为 `7 passed, 0 failed`，未发现非确定性分支。

原型支持四项初步结论：

1. `CompanionMind` 仍可作为唯一深模块，调用者仍只接收一个版本化策略；不需要新增 `PersonalityEngine` 或第二事实源。
2. 合成规则应表达为“个体化候选 + 多层允许包络与硬约束求交集”，而不是容易受代码顺序影响的线性覆盖表。
3. 正式 `CompanionPolicy` 至少需要一个结构化 `expression_style` 投影，才能承载探索取向、表达活力和思路组织；现有回复长度、问题预算和 `age_expression` 无法在不混淆领域语义的情况下代替它。
4. 主动气质是机会排序偏好，`initiative_level` 是实际权限上限；同理，出生气质和当前有效表达必须可同时观察，不能把临时钳制写回出生值。

以上是原型证据，不代表生产代码已经实现。

## 已确认

产品确认采用“个体化候选与多层约束求交集”的合成模型，不采用由代码先后顺序决定胜负的覆盖链。出生气质与后天磨合表达倾向；年龄、关系、互动契约、当前场景、负反馈、端侧能力及身份安全表达本次允许范围；临时限制不得改写出生气质。

产品确认在现有 `CompanionPolicy` 内增加一个不持久化、不可由模型或调用端直接写入的结构化 `expression_style`。它只投影本轮最终的 `exploration_orientation`、`expression_energy`、`thought_organization`、`humor_level` 和 `initiative_bias`；出生玩心编译为本轮幽默强度，出生主动性编译为机会排序偏好，实际主动权限仍由独立的 `initiative_level` 表达。

产品确认 `CompanionMind` 内部生成临时策略决策轨迹。轨迹只使用固定安全原因码，不含聊天原文、私人记忆、模型推理或自由文本用户标签；不进入 prompt，不作为个人记忆长期保存。模型和普通调用端只接收最终策略，测试和开发者诊断可以使用安全轨迹，普通用户只接收必要的自然语言结果说明。
