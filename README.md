# 金潮杯博物馆项目

金潮杯博物馆项目是一套面向博物馆研学场景的可考证语音讲解系统。项目使用 ESP32 终端承载语音、触摸、屏幕和扬声器交互，服务端负责展品上下文、审核知识检索、路线推进、回答约束、模型编排和运营记录。

本仓库是金潮杯博物馆项目的服务端仓库。硬件固件位于 `D:\AI_Pet\museum-firmwire`。

## 当前状态

截至 2026 年 8 月 10 日，当前工作区已实现比赛版单展品纵向链路，包括：

- ESP32 WebSocket 实时连接和音频链路；
- OTA 接口；
- ASR、受审核事实约束的 LLM 回答、TTS 和 VAD；
- 流式 TTS、设备播放确认和中断控制；
- 战国水晶杯展品、事实、来源、发布版本和交互审计；
- 临时游客会话、设备点位和严格 `museum_state` 协议；
- 固件端展品、检索、有依据回答和资料不足状态；
- 浏览器语音链路调试工具（非比赛主链路）。

比赛运行路径中的学生身份、声纹、课程、待办、天气、长期陪伴记忆、主动提醒、门铃和旧 Overview 服务已移除。当前正式传输路径为 `/museum/v1/` 和 `/museum/ota/`；服务端暂保留 `/xiaoxin/v1/`、`/xiaoxin/ota/` 等历史路径，仅用于兼容尚未迁移的设备协议，不代表继续沿用旧陪伴业务。

服务端活动数据必须使用独立的博物馆数据目录，不能复用旧项目 `data` 挂载。启动检查会拒绝 `xiaoxin_*.db`、旧控制数据库、旧知识目录和课程/待办配置段；旧数据只能留在活动挂载之外的取证或归档中。生产部署参数见 [`121.43.33.0` 博物馆服务部署方案](docs/production-deployment-plan.md)。

当前结论来自源码检查和自动化测试，不等同于真机验收。本轮尚未取得包含设备标识、固件提交、服务端提交、操作步骤、终端表现和异常日志的可复核记录，因此麦克风、ASR、扬声器、屏幕、触摸、弱网恢复和 OTA 仍须在目标设备上逐项验证。

## 重建原则

1. 保留稳定的语音、设备、模型和 OTA 基座。
2. 新建独立的博物馆业务运行时，不在旧陪伴运行时中继续叠加条件分支。
3. 展品事实必须绑定来源、审核状态和内容版本。
4. 游客模式只改变表达方式，不改变事实。
5. 默认使用临时游客会话，不依赖声纹或长期个人画像。
6. 比赛版本先完成一台真机、一个展区和一条完整可验证链路。

## 目标主链路

```text
ESP32 语音输入
  -> ASR
  -> 博物馆对话运行时
  -> 设备/展品上下文
  -> 已审核事实检索
  -> LLM 生成
  -> 事实与表达守卫
  -> 流式 TTS 和屏幕状态
  -> 交互审计与未命中记录
```

## 路径策略

`/museum/v1/` 和 `/museum/ota/` 是当前正式设备路径。`/xiaoxin/v1/`、`/xiaoxin/ota/` 及旧 activation 别名只承担历史传输兼容；旧 `/api/miniprogram/*` 控制接口已移除，当前仓库不额外承诺未实现的管理 API。

## 开发纪律

- 不把旧代码中的 `xiaoxin`、`xiaozhi` 机械批量改名。
- 不把旧学生陪伴能力包装成博物馆功能。
- 服务端与固件协议变更必须同步设计和验收。
- 只有真实通过的链路才可以写入申报材料和演示说明。
