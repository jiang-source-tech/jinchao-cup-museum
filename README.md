# 小芯博物馆智能伴游系统

小芯是一套面向博物馆研学场景的可考证智能伴游系统。项目使用 ESP32 终端承载语音、触摸、屏幕和扬声器交互，服务端负责展品上下文、审核知识检索、路线推进、回答约束、模型编排和运营记录。

本仓库是小芯的服务端仓库。硬件固件位于 `D:\AI_Pet\museum-firmwire`。

## 当前状态

截至 2026 年 8 月 9 日，仓库已经具备可复用的设备与 AI 基座，包括：

- ESP32 WebSocket 实时连接和音频链路；
- OTA 接口；
- ASR、LLM、TTS、VAD 和工具调用适配；
- 流式 TTS、设备播放确认和中断控制；
- 设备在线状态、屏幕消息和固件遥测；
- 浏览器数字人调试工具。

博物馆业务层尚未完成。当前代码中的学生身份、声纹、课程、待办、长期陪伴记忆和主动提醒属于旧项目遗留，不代表金潮杯项目需求。

## 重建原则

1. 保留稳定的语音、设备、模型和 OTA 基座。
2. 新建独立的博物馆业务运行时，不在旧陪伴运行时中继续叠加条件分支。
3. 展品事实必须绑定来源、审核状态和内容版本。
4. 游客模式只改变表达方式，不改变事实。
5. 默认使用临时游客会话，不依赖声纹或长期个人画像。
6. 比赛版本先完成一台真机、一个展区和一条完整可验证链路。

## 目标主链路

```text
ESP32 语音输入
  -> ASR
  -> 博物馆对话运行时
  -> 设备/展品上下文
  -> 已审核事实检索
  -> LLM 生成
  -> 事实与表达守卫
  -> 流式 TTS 和屏幕状态
  -> 交互审计与未命中记录
```

## 路径策略

`/xiaoxin/v1/` 和 `/xiaoxin/ota/` 是小芯设备传输路径，继续保留。新的博物馆管理与业务接口使用 `/api/museum/*`，不再扩展旧 `/api/miniprogram/*` 业务。

## 开发纪律

- 不把旧代码中的 `xiaoxin`、`xiaozhi` 机械批量改名。
- 不把旧学生陪伴能力包装成博物馆功能。
- 服务端与固件协议变更必须同步设计和验收。
- 只有真实通过的链路才可以写入申报材料和演示说明。
